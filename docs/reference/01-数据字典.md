### 4.1 `scopes` / `exclude` 结构（范围筛选器）

| 键 | 类型 | 语义 |
|---|---|---|
| `textbookVersions` | string[] | 教材版本（`人教版`） |

| `difficulties` | string[] | 难度（**中文值**：`简单`/`中等`/`较难`） |
| `versionTypes` | string[] | 版本类型（在范围层面先滤一次版本） |
| `starred` | boolean | 仅星标（当前无数据） |
| `mustInclude` | boolean | 仅必出题（当前无数据） |
| `enabled` | boolean | `false` 时只取已禁用条目（特殊用途） |

**范围语义（v2 · 册别分组细化，务必按此理解）**：
- 勾了册别 + 章/节时：**被"细化"的册**要求**同一条教材记录**同时命中（册+章+节）；**未被细化的册**整册生效。
- 判定"某册是否被细化"= 题库中是否存在 `{book:该册, chapter∈勾选章}` 或 `{book:该册, section∈勾选节}` 的记录（数据驱动，不依赖章节树）。
- 未勾册别时：章/节为**跨册**语义；章+节同时勾选要求**同一条记录**同时命中。
- 其余维度之间是**"且"**关系。

> 例：勾「九上 + 九下 + 必修一 + 第一章 + 第一节」= 九上/九下**整册** ∪ 必修一·第一章·第一节（不会因为"第一章"这个条件把九年级两册整体排除）。

### 6.3 D 题型挖空策略 `BLANK_STRATEGIES`

`blankProducts` 缺全部生成物 ｜ `blankOneProduct` 缺某一个生成物 ｜ `blankOneReactant` 缺某一个反应物 ｜ `blankCoefficients` 缺系数 ｜ `blankCondition` 缺条件 ｜ `custom` 自由点选挖空

（由引擎按版本内容自动挑选：有生成物→缺产物；反应物≥2→缺一个反应物；有非 1 系数→缺系数；有条件→缺条件）

### 6.4 版本策略 `VERSION_STRATEGIES`

| key | 界面文案 | 引擎行为 |
|---|---|---|
| `chemicalOnly` | 只出化学方程式 | 只保留 `type='chemical'` |
| `ionicOnly` | 只出离子方程式 | 只保留 `type='ionic'` |
| `preferChemical` | 优先化学方程式 | 有 chemical 就用 chemical，否则保留其余全部版本 |
| `preferIonic` | 优先离子方程式 | 有 ionic 就用 ionic，否则保留其余全部版本 |
| `allAvailable` | 所有可用版本均可 | 不过滤（6 类全可） |
| `custom` | 教师指定版本类型 | 按 `allowedVersionTypes` 过滤 |

## 9. 引擎函数契约（实现时必须遵守）

| 函数 | 签名 | 语义要点 |
|---|---|---|
| `refineBooksByScope(entries, filter)` | → `Set<册名>` | 预计算"被细化的册"，决定册/章/节如何组合 |
| `entryInScope(entry, filter, refined)` | → boolean | 范围匹配（语义见 §4.1） |
| `scopedEntries(library, filter)` | → `entry[]` | 范围内条目（**含禁用条目**，调用方自行过滤） |
| `versionsForEntry(entry, strategy, allowedTypes, scopeTypes)` | → `version[]` | 按版本策略取版本（`scopeTypes` 是范围层的版本类型过滤） |
| `buildCandidates(library, settings, opts)` | → `{entry, version}[]` | 候选池：先滤 `enabled!==false`，再范围 AND 项目范围，再排除 `exclude`，最后展开版本 |
| `availableQuestionTypes(candidates)` | → `string[]` | 候选池实际可出题型：`['B','D','E']` + 有 description 加 `C` + 有 openPrompt 加 `H` |
| `generate(library, settings, opts)` | → `{ok:true, items, notices}` 或 `{ok:false, reason, message}` | 组卷主入口 |
| `allocateTypes(total, typeCounts, availTypes, prealloc)` | → `{counts}` 或 `{error}` | 题型数量分配（不足则用**可出题型**随机补足） |
| `allocateDifficulties(total, settings)` | → `targets[]` | 难度目标序列（**软约束**，不满足不报错） |
| `makeItem(entry, version, qType)` | → item | 生成题目对象 |
| `pairKey(version, qType)` | → string | 学习项目计数键（版本 + 题型） |

### 9.1 `generate` 的失败返回（`ok:false`）

| reason | 触发条件 | 附带字段 |
|---|---|---|
| `shortage` | 填不满总题数（候选池不够 / 题型素材不够） | `need`（还差几题）、`available`（候选**版本**数）、`message` |
| `roundShortage` | 因学习项目轮数限制填不满，但放开轮数就能填满 | `need`、`available`、`availableUnlimited: true`、`message` |
| `manualExceed` | 手动选题数 > 总题数 | `message` |
| `mustExceed` | 必出题数 > 总题数 | `message` |
| `typeOverflow` | 题型指定数量之和 > 总题数 | `message` |

> ⚠️ **`available` 是候选"版本"数，不是"可出题数"**。例：全库·全版本求 400 题 → `available=553`，但实际只出得满 **392** 题（条目数，默认去重口径）。
> 对外报"可出 N 题"必须用**条目数**（见 `04-可出题量预检.md`）。

### 9.2 `generate` 的 `opts`

| 键 | 含义 |
|---|---|
| `projectScope` | 学习项目范围（与 `settings.scopes` 为 **AND**；空对象 = 全库） |
| `projectCounts` | 项目计数表（键 = `pairKey(version, qType)`） |
| `round` | 当前轮数（与 `projectCounts` 配合限制"本轮已出过"的题目） |
| `allowOverRound` | 允许超轮数 |

### 9.3 item（题目对象）结构

```json
{
  "itemId": "q_...", "entryId": "R0009", "versionId": "R0009-chemical",
  "versionType": "chemical", "questionType": "B", "blankStrategy": "blankProducts",
  "customPrompt": null, "locked": false, "showAnswerLine": null,
  "answerLineHeightPt": null, "pageBreakAfter": false,
  "snapshot": { "entryName": "…", "description": "…", "openPrompt": "",
                "difficulty": "中等", "version": { /* 版本完整快照 */ },
                "entryId": "R0009", "takenAt": "…" }
}
```

> **注意**：`snapshot.version` 是出题当时的**版本快照**——这是"历史卷子可复现"的现有机制，可作为需求讨论的参考。

### 9.4 最大题量（去重口径）

| 去重设置 | 一份卷子的题量上限 |
|---|---|
| 默认（同条目不重复） | **候选条目数**（`buildCandidates` 结果里的 distinct entry） |
| `allowSameEntryDifferentVersion=true` | **候选版本数**（entry×version 对数） |
| `allowDuplicateEntry=true` | 无上限 |

> 请求题量超过上限时，`generate` 返回 `{ok:false, reason:'shortage', need, available}`（见 §9.1）。
> 该上限已用引擎实测验证，见 `04-可出题量预检.md` 的「口径验证」小节。

## 10. 坑清单（务必原样转述给需求讨论）

1. **难度两套写法**：题库 `简单/中等/较难` ↔ 引擎 `simple/medium/hard`（§6.5）。
2. **默认版本策略是 `chemicalOnly`**：全库 392 条里只有 **301 条**有化学方程式版本 → 默认策略直接损失 91 条；选择性必修 3（有机）**0 条**有离子版本，选择性必修 2 只有 6 条条目。
3. **H 题型不可用**：`openPrompt` 全空。
4. **"必出题/星标"无数据**：`mustInclude`、`starred` 全 false。
5. **字段存在 ≠ 有值**：`tags` 字段 392 条都有，但只有 105 条非空。
6. **`textbooks` 含完全重复记录**，统计必须先去重。
7. **章节树只覆盖高中 5 册**（19 章 50 节）；九年级两册靠教材记录文本（"第X单元 / 课题N"）。
8. **范围语义是"册别分组细化"**（§4.1），不是全局"且"；理解错会导致"范围越选越少"。
9. **题量不足会明确报错，但报的数字有陷阱**：返回 `{ok:false, reason:'shortage', need, available}`；其中 `available` 是**候选版本数**（全库全版本 = 553），而**真正能出的题量是条目数**（392）。对外提示必须用条目数，否则会承诺出不了的题量。
10. **难度是软约束**：`difficultyCounts` 不满足也不报错，只在 `notices` 里说明"有 N 题难度与设定不同"。
11. **写回 `questionCount`/`lastUsedAt` 会改变题库状态与学习项目轮数**（`pairKey` = 版本+题型）。
12. **多价离子必须 `^` 记法**（`SO4^2-`）；`\be-\b` 对尾随 `e-` 不匹配（历史坑）。
