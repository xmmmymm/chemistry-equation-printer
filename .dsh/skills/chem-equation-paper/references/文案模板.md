# 文案模板 · 复述框 / 报告 / 拒绝 / 红字提示

> 用途：agent 与老师对话时**直接套用**的话术。原则：老师不懂技术也能看懂
> 「要出几题、什么范围、存哪、叫什么名」。
> 变量写法 `{xxx}` 表示替换位；`[…]` 表示可选段。

---

## 一、intake（4 问，一次问完）

```
出方程式卷子前，先跟你确认 4 件事：

1）场景：课后作业 / 课堂限时练 / 备考练习？（默认：课后作业）
2）范围：哪个册、哪一章哪一节？直接说就行（例：「必修一第一章」「选必 3 的烃」「全库」）
3）版本策略：这道题要什么写法？
     · 只出化学方程式（量最少：全库 301 题）
     · 优先化学方程式（推荐，量最大：全库 392 题）
     · 只出离子方程式 / 优先离子方程式
     · 所有可用版本都行
     · 我指定（比如只要电离、水解）
4）附加要求：有没有别的？比如「要 15 题」「来 2 道文字描述题」「钠相关至少 2 题」「别出有机」；没有就说「没有」
```

### intake 轮的两个提示（有才说，没有别提）

```
⚠ 上次有导出没成功（{date}，{n} 项：{channel}）。要现在重试吗？
```

```
ℹ 题库数据是 {数据时间} 的（{n} 条），但本地题库与数据锁不一致（data/ 被项目之外改动过）——
   不影响出卷，只是提醒你这份卷子用的是当前磁盘上的题库。要重新锁定请说一声（npm run data:lock）。
```

## 二、复述框（确认后才执行）★ 最重要

```
📋 请确认这一份卷子（确认后我就开始出）：

【场景】{场景中文}
【题量】{totalCount} 题
【题型】{题型说明}
【难度】{难度说明}
【版本策略】{策略中文}
【范围】{范围中文}
        └ 归一依据：{逐条映射，如「必修一」→ 必修第一册；「离子反应」→ 必修第一册 / 第一章 物质及其变化 / 第二节 离子反应}
【可出题数】这个范围最多能出 {authoritativeCount} 题（按条目数，同一道题一卷只出一次）
【导出】PDF 题目卷 + 答案卷；Word 题目卷 + 答案卷[；图片]
【存放位置】{outputDir}
【文件名】
   {file1}
   {file2}
   {file3}
   {file4}
【题库数据】{数据时间}（{entries} 条 / {versions} 版本）· {数据锁状态}
【intake 覆盖度】{explicit 几项当次问到 / memory 几项沿用上次 / default 几项按默认}

要改哪一项直接说；没问题就说「可以」。
```

### intake 覆盖度怎么摆（`intakeCoverage`，AC-18）

老师不需要看字段名，只要看懂「**哪些是我说的、哪些是你替我定的**」。三档：

| verdict | 复述框里怎么写 |
|---|---|
| `intake-complete` | 「本次参数都由你刚才说的确定 ✓」（`explicitKeys` 覆盖必问 3 项） |
| `intake-incomplete` | 「⚠ 这几项**不是你说的**，是沿用上次/按默认定的：{unasked 中文名}——确认一下？」 |
| `blocked` | 走 §四 的 ASK 话术（版本策略没问出来） |

逐项来源的中文名（`items[].key` → 中文）：`scenario` 场景、`scope` 范围、`versionStrategy` 版本策略、
`totalCount` 题量、`questionTypeCounts` 题型分布、`difficulty` 难度目标、`extraAcceptance` 附加要求、
`export` 导出通道、`outputDir` 存放位置。

现成话术（`intake-incomplete`）：

```
⚠ 说明一下这份卷子里「不是你这次说的」的部分（避免我替你定了却没告诉你）：
   · {项1}：{值1}　← 沿用上次
   · {项2}：{值2}　← 系统默认
   其余都是你刚才说的。这几项要改吗？不改我就按这个出。
```

> ⚠ 引擎侧的硬保证：**不带 `--confirmed` 一个字节都不生成**（见 §四·确认闸门）。
> 所以「先复述、老师点头才出」现在不只是话术——你不点，卷子就出不来。

### 题型说明的三种写法

| 情况 | 文案 |
|---|---|
| 全 0（自动） | 自动搭配（B 给反应物写产物、C 文字描述写方程式、D 部分空格补全、E 配平；开放题 H 题库无素材，恒不出） |
| 指定了 | B {n1} 题、C {n2} 题、D {n3} 题、E {n4} 题 |
| B4 缩过 | B {b1} 题、C {c1} 题、D {d1} 题、E {e1} 题　（你原本要 B{b0}/C{c0}/D{d0}/E{e0}，共 {sum0} 题超过总题数 {totalCount}，已按比例缩成上面这样，总数正好 {totalCount}） |

### 难度说明的三种写法

| 情况 | 文案 |
|---|---|
| 不限制 | 不限制（按题库实际分布） |
| 指定了 | 简单 {s} 题、中等 {m} 题、较难 {h} 题（难度是软要求，尽量满足） |

### 题库数据锁状态写法

| 状态 | 文案 |
|---|---|
| 一致 | 与数据锁一致 ✓ |
| 不一致 | ⚠ 本地题库与数据锁不一致（data/ 被项目之外改动过），本次仍按当前题库出卷 {数据时间}——不阻塞出卷，报告里会标注；合法改动跑 `npm run data:lock` 重新锁定 |
| 数据不可读 | 题库数据读不到（出卷会直接失败并给出恢复指引） |

## 四、拒绝话术（ASK / B7 / B6 / B11 / CONFIRM_REQUIRED）

### 确认闸门（`CONFIRM_REQUIRED`）——不是出错，是「还没点头」

不带 `--confirmed` 跑 `run-paper` 时，app 只回这份 JSON（`exitCode 2`），**零卷子产出**：

```
⏸ 还没开始生成——先请你确认上面那份复述框 + 覆盖度报告。
   （本次没有产生任何文件；确认后我带 --confirmed 重跑，立刻出卷）
```

老师说「可以 / 没问题 / 出吧」之后：

```powershell
node tools/run-paper.js {jobPath} --confirmed
```

> `intakeCoverage.verdict = intake-incomplete` 时，**先**按 §二 的话术点明哪几项不是老师说的，
> 再请老师确认；不要直接把 `--confirmed` 打上去。
> 豁免：`--render-check` 与 `job.dryRun:true` 不产交付物，不受闸门约束。

### ASK · 版本策略没问就出卷（`ASK_VERSION_STRATEGY`）

预检会**直接拦下**（`exitCode: 2`，不进导出）——因为规格要求版本策略「每次必问、无静默默认」。
看到这个 code 说明你漏问了第 3 问，回 intake 补问，别硬出。

```
⚠ 还差一件事没确认：这份卷子的**写法**。
   同一道题有化学方程式 / 离子方程式等几种写法，选哪个会直接影响出题数量和卷面内容：
     · 只出化学方程式（量最少：全库 301 题）
     · 优先化学方程式（推荐，量最大：全库 392 题）
     · 只出离子方程式 / 优先离子方程式
     · 所有可用版本都行
     · 我指定（比如只要电离、水解）
   你说一个，我就接着出。
```

> `restate.versionStrategy` 也会如实回显 `"ASK"`（**不会**伪装成 `chemicalOnly`），
> `restate.versionStrategyEffective` 才是「不问就会落到」的兜底值，仅供你说明后果用。

### B7 · 要开放题（H）

```
❌ 开放题（H）出不了：题库里 392 条条目的「开放题干」字段全是空的，没有素材。
✅ 建议改成 C 题型（给文字描述写方程式）——题库每条都有文字描述，C 一定能出。
   要的话我把这 {n} 道改成 C 题型，其余不变，可以吗？
```

### B7 · 要「必出题」机制 / 星标筛选

```
❌ 「必出题」机制用不了：题库里 mustInclude 字段 392 条全是 false，没有标记过。
✅ 换个办法：你直接把要出的题号/名称告诉我，我用手选必出（manualEntryIds）钉进卷子。

❌ 「星标」筛选用不了：题库里 starred 字段也全是 false。
✅ 换个办法：题库有标签（高频 / 易错 / 月考重点 / 期中考前 / 基础必会 / 补充题），
   但只有 105 条有标签。要按标签筛的话告诉我用哪个标签，我先查能命中几条。
```

### B6 · 范围零命中 / 多候选

```
❌ 「{input}」这个说法我在题库里找不到对应项，不能瞎猜（也不会自动放宽到全库）。
   题库里有的{维度}是：
     {候选列表}
   你选一个，或者说个更具体的说法？

⚠ 「{input}」能匹配到多个{维度}，选一个：
     ① {候选1}
     ② {候选2}
     ③ {候选3}
```

### B11 · 手选条目失效

```
❌ 你点的这几道题现在用不了：
   {id}　{name}　→ {原因}
   原因可能是：条目被删了 / 被禁用了 / 当前版本策略下没有可用版本 / 不在本次范围内。
✅ 请把失效的剔掉，或换成别的条目。剔完我立刻出卷。
```

## 五、题量不足：四选项流（B1）

```
⚠ 这个范围出不满 {totalCount} 题。

   范围：{范围中文}
   版本策略：{策略中文}
   实际能出：{authoritativeCount} 题（按条目数算，同一道题一卷只出一次）
   {zeroHit ? '（命中 0 条条目——这是范围/策略组合的问题，不是"版本策略损失"能解释的）' : ''}

   四条路，你挑一条：

   ① 减题量：{totalCount} → {authoritativeCount} 题
   ② 放宽范围：去掉部分限制（你说去哪个，我不自动放宽）
   ③ 换版本策略：改成「{更优策略}」，能出 {更优数量} 题
        （各策略对照：{策略1} {n1} 题｜{策略2} {n2} 题｜…）
   ④ 允许同一道题出不同写法（临时）：上限从 {authoritativeCount} 提到 {versionCount} 个候选

   注意：引擎报的「可用 {available}」是**候选版本数**，不是能出的题数；
   能出几题一律按**条目数**算。
```

### 题型不可出

```
⚠ 你要的 {题型} 题型在当前范围出不了（这个范围的候选里没有可用的 {题型} 素材）。
   当前范围能出的题型：{availableTypes}
   要么换题型，要么放宽范围，你看？
```

## 八、常见追问的现成回答

| 老师问 | 回答 |
|---|---|
| 「怎么才出 6 题？我要 10 题」 | 这个范围总共只有 6 条不同的题目（同一道题一卷只出一次）。要么减到 6 题，要么放宽范围，要么允许同一条目出不同写法（上限 {versionCount} 个候选）。 |
| 「为什么全是化学方程式？」 | 版本策略选了「优先化学方程式」——有条目有化学写法就只用化学写法。要混离子/电极等写法，改成「所有可用版本都行」。 |
| 「这卷子存在哪？」 | 本项目的 `out\{日期}\`，文件名 `{日期}_{场景}_{题量}题_题目.pdf` 这样。**不会**写进你原来的题库应用。 |
| 「会不会改我的题库？」 | 不会。这个 skill 出卷只**读**本项目自己的题库（`data/`），不写题库；引擎上游项目更是只读——出卷前后上游所有文件的 sha256 完全不变（有验收用例盯着）。 |
| 「答案呢？」 | PDF 和 Word 都是双卷：`_题目` 和 `_答案` 两个文件。 |
| 「能出图片吗？」 | 可以，点名就行（默认不出）。默认规格：PNG、2 倍缩放、微软雅黑 16pt、只出主版本化学方程式。 |
| 「卷面格式能改吗？」 | 格式是固定的（A4 纵向、2cm 边距、宋体+TNR、16/12/10.5pt、单倍行距、题距 6pt、自动分页、页脚页码）。要改得改 skill 的 `layout.yml`。 |
| 「能一次出两份不同的吗？」 | 一次一份（批量/AB 卷明确不做）。要两份就分两次。 |
| 「能出开放题/探究题吗？」 | 不能，题库没有开放题干素材。可以用 C 题型（给文字描述写方程式）代替。 |
| 「为什么还要我再确认一次？」 | 因为同一道题有化学/离子多种写法、题量一变可出题数也变，出错了是返工级。引擎侧也做了硬保证：**你不确认，卷子一个字节都不会生成**（`--confirmed` 才放行）。 |
| 「你怎么知道哪些是我说的？」 | 预检会逐项标注来源：`explicit`（你这次说的）/ `memory`（沿用上次）/ `default`（系统默认），就是复述框里那块「intake 覆盖度」。这样我漏问了哪一项，你当场能看见。 |
| 「沿用上次的范围，还用再说一遍吗？」 | 不用。直接说「跟上次一样」即可，覆盖度报告会标明「范围 ← 沿用上次」，你确认就行。 |
